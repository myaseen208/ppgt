# P-BEST: PP-Based Designs and Clinical Context

## 1 Abstract

This vignette distinguishes the standard PP-based 48-pool P-BEST family
from the later clinical P-BEST discussion. It also separates
paper-aligned matrix content from the package-specific helpers that live
around the P-BEST design family.

## 2 The Standard PP-Based P-BEST Family

The standard PP-based P-BEST matrix family in the package is generated
by `pp_matrix(q = 8, d = 3, nl = 6, N = 384)`, which gives \\J = 48\\
pools for \\N = 384\\ individuals.

At the matrix level, this is a PP design with \\ q = 8, \qquad d = 3,
\qquad n_l = 6, \qquad N = 384, \\ so the full PP identity \\ J = n_l q
= 48 \\ matches the standard 48-pool family used in the package
documentation.

## 5 Matrix-Family Alignment Versus Protocol Claims

The matrix call above is the package’s reference-aligned claim for the
PP-based 48-pool family. That claim is narrower than saying that the
package reproduces every protocol, decoder, or laboratory workflow
associated with later P-BEST variants.

- Matrix-family alignment: the structural PP-based 48-pool construction
  represented by `pp_matrix(q = 8, d = 3, nl = 6, N = 384)`
- Package decoding:
  [`pp_comp()`](https://myaseen208.github.io/ppgt/reference/pp_comp.md)
  and
  [`pp_decode()`](https://myaseen208.github.io/ppgt/reference/pp_decode.md)
  are package decoding helpers built around the matrix interface
- Clinical package helpers: package-specific objects such as
  [`pbest_clinical_matrix()`](https://myaseen208.github.io/ppgt/reference/pbest_clinical_matrix.md)
  are documented as separate package functionality

This distinction matters because a pooling matrix is only one layer of a
full testing protocol. The matrix-level claim concerns the design
\\\mathbf{M} \in \\0,1\\^{48 \times 384}\\ and its PP structure.
Laboratory workflow rules, Ct-based interpretation, retesting policies,
and stage-2 follow-up belong to different layers.

## 7 Distinguishing The 48-Pool Family From Later Clinical P-BEST

The 2020 P-BEST references and the later 2024 clinical P-BEST work
should not be conflated.

- The 48-pool PP-based family is the Reed-Solomon / PP-based
  configuration represented in the package by
  `pp_matrix(q = 8, d = 3, nl = 6, N = 384)`.
- The later clinical discussion concerns higher-capacity operational
  designs, workflow choices, Ct-based interpretation, and clinical
  deployment issues.

The package therefore keeps two separate stories:

- a PP-based matrix family story for the 48-pool algebraic design
- a clinical package-helper story for later operational high-capacity
  layouts

## 8 Package-Specific Boundary

The matrix constructor above is the paper-aligned PP-based
configuration. The package also provides higher-level helpers around
P-BEST-style workflows.

- [`pp_decode()`](https://myaseen208.github.io/ppgt/reference/pp_decode.md)
  is a package decoding pipeline.
- [`pbest_clinical_matrix()`](https://myaseen208.github.io/ppgt/reference/pbest_clinical_matrix.md)
  is a package clinical-design constructor.

These helpers are package functionality. They are not blanket claims
that the package reproduces every stage of each P-BEST workflow exactly.
