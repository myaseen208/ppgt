# HyperEC: Package-Specific Experimental Extension

## 1 Abstract

This vignette covers the package-specific experimental HyperEC
extension. The functions
[`hyper_ec_matrix()`](https://myaseen208.github.io/ppgt/reference/hyper_ec_matrix.md)
and
[`hyper_ec_decode()`](https://myaseen208.github.io/ppgt/reference/hyper_ec_decode.md)
are not the HYPER paper design itself. They are documented as
package-specific experimental tools built on top of a base HYPER matrix.

## 2 Scope And Limits

The current HyperEC interface combines:

1.  a base HYPER matrix
2.  additional parity-derived rows
3.  a bounded decoder that searches for a low-weight correction pattern

This should be interpreted as a package experiment. It is not an exact
implementation of a Hong et al. HyperEC procedure.

The returned object contains a base HYPER matrix together with
additional parity-derived rows. If the combined incidence matrix is
denoted by \\\mathbf{M}\_{\mathrm{EC}}\\, then the package reports \\
\mathbf{M}\_{\mathrm{EC}} = \begin{bmatrix} \mathbf{M}\_{\mathrm{base}}
\\ \mathbf{M}\_{\mathrm{parity}} \end{bmatrix}, \\ but the exact
parity-generation rule and the decoder interpretation are
package-specific rather than paper-backed claims.

## 6 Interpretation

The object returned by
[`hyper_ec_decode()`](https://myaseen208.github.io/ppgt/reference/hyper_ec_decode.md)
is best read as a stage-1 candidate screening result under the package’s
current parity model, not as a general error-correction guarantee.

This vignette is intentionally separate from the HYPER vignette so that
the package-specific extension is not presented as paper-aligned HYPER
