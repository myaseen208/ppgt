# Compare Built-In Group Testing Designs

Generate several built-in pooling designs and summarize their structural
properties in a common comparison object. The current implementation
compares the package constructors for P-BEST, Tapestry, HYPER, and the
package-specific experimental parity-augmented
[`hyper_ec_matrix()`](https://myaseen208.github.io/ppgt/reference/hyper_ec_matrix.md)
extension.

## Usage

``` r
compare_all_designs(n = 256, prevalence = 0.01, alpha = 0.2)
```

## Arguments

- n:

  Integer scalar giving the target number of individuals. This is the
  intended column dimension \\N\\ for the Tapestry, HYPER, and
  experimental HYPER-EC comparison branches. The default is `256`.

- prevalence:

  Numeric scalar giving the assumed common prevalence \\p_i = p\\ used
  to define the approximate expected number of positives \\k = \max\\1,
  \lfloor Np \rfloor\\\\ for design constructors that require an input
  sparsity level. It must lie in \\(0,1)\\; the default is `0.01`.

- alpha:

  Numeric scalar giving the parity-overhead factor for the
  package-specific experimental
  [`hyper_ec_matrix()`](https://myaseen208.github.io/ppgt/reference/hyper_ec_matrix.md)
  branch. The default is `0.20`. In that branch the number of added
  parity pools is driven by \\\alpha\\.

## Value

A named list with five components:

- `pbest`:

  A list with components `matrix` and `metrics` for the P-BEST branch.

- `tapestry`:

  A list with components `matrix` and `metrics` for the Tapestry branch.

- `hyper`:

  A list with components `matrix` and `metrics` for the HYPER branch.

- `hyper_ec`:

  A list with components `matrix` and `metrics` for the experimental
  parity-augmented HYPER-EC branch.

- `comparison_table`:

  A data frame with one row per design and columns `Design`,
  `Samples_n`, `Pools_m`, `Efficiency_m_n`, `Lambda_max`, and
  `Error_Correction`.

Each `metrics` component is itself a named list. For successful design
generation it contains summary statistics such as the achieved number of
individuals \\N\\, the number of pools \\J\\, the ratio \\J/N\\, the
maximum column sum \\\max_i \|\mathcal{J}\_i\|\\, and row-size summaries
based on \\n_j = \|\mathcal{P}\_j\|\\. If a branch fails, its metrics
entry contains a design label and a failure note. The `Error_Correction`
field is a package-specific comparison label for this helper; it is not
a formal paper-backed guarantee.

## Details

Let \\\mathbf{M} \in \\0,1\\^{J \times N}\\ denote a pooling matrix,
where \\N\\ is the number of individuals and \\J\\ is the number of
pools. This function builds one design object for each supported branch
and reports a common set of structural summaries. For every successfully
generated design, the comparison metrics are derived from \$\$n_j =
\|\mathcal{P}\_j\| = \sum\_{i=1}^N M\_{ji}\$\$ and \$\$w_i =
\|\mathcal{J}\_i\| = \sum\_{j=1}^J M\_{ji}.\$\$ The reported efficiency
ratio is \$\$\frac{J}{N},\$\$ which is stored in the output as
`Efficiency_m_n`. The reported `Lambda_max` is a display label for the
maximum number of pools containing any single individual,
\$\$\lambda\_{\max} = \max\_{1 \le i \le N} \|\mathcal{J}\_i\| = \max_i
w_i.\$\$ The row-size summaries are the empirical mean and standard
deviation of \\n_j\\.

The comparison procedure uses the following package-specific constructor
choices. For Tapestry and the experimental HYPER-EC branch, the expected
number of positives is approximated by \$\$k = \max\left\\1,
\left\lfloor N p \right\rfloor\right\\.\$\$ For HYPER, the baseline
number of pools is set heuristically to \$\$J\_{\mathrm{base}} =
\max\left\\\left\lceil 4 k \log(N) \right\rceil, \left\lceil 0.15 N
\right\rceil\right\\,\$\$ followed by an adjustment to the nearest even
integer so that the `q = 2` constructor call is admissible. The P-BEST
branch always uses the package's fixed standard constructor call
`pp_matrix(q = 8, d = 3, nl = 6, N = 384)`, so its achieved column
dimension is not forced to equal the input `n`. The experimental
HYPER-EC branch uses
`hyper_ec_matrix(n = n, k = k, m_base = m_hyper, q = 2, alpha = alpha)`
and should be interpreted as a package-specific extension rather than
the Hong et al. HYPER paper design.
