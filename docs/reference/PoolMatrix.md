# Construct a Pooling Design Matrix by Family

Dispatch to one of the existing pooling-design constructors in ppgt
using a user-facing family label. The function is a convenience wrapper
over the package's structured constructors and returns only the pooling
matrix \\\mathbf{M}\\. It does not claim that \\d\\ alone uniquely
determines a pooling matrix across design families.

## Usage

``` r
PoolMatrix(
  family = c("pp", "pbest", "hyper", "separable", "disjunct", "dorfman", "array", "bibd",
    "hypercube", "kirkman", "pg"),
  d = NULL,
  N = NULL,
  q = NULL,
  J = NULL,
  method = NULL,
  verify = TRUE,
  seed = NULL,
  ...,
  verbose = FALSE
)
```

## Arguments

- family:

  Character scalar selecting the constructor family. Supported values
  are `"pp"`, `"pbest"`, `"hyper"`, `"separable"`, `"disjunct"`,
  `"dorfman"`, `"array"`, `"bibd"`, `"hypercube"`, `"kirkman"`, and
  `"pg"`.

- d:

  Optional integer scalar. This argument is passed only to families for
  which \\d\\ is a native parameter, such as Polynomial Pools, separable
  designs, disjunct designs, and hypercube designs. For other families
  it is ignored unless explicitly documented for the selected
  constructor.

- N:

  Optional integer scalar giving the number of individuals. When the
  selected family uses \\N\\ directly, this value is forwarded to the
  underlying constructor. For design families whose native interface
  uses a different symbol such as \\v\\, `PoolMatrix()` uses `N` only as
  a convenience alias when that mapping is exact.

- q:

  Optional integer scalar. This argument is forwarded only to families
  where \\q\\ is a native parameter, such as Polynomial Pools, HYPER,
  hypercube designs, and projective-plane designs.

- J:

  Optional integer scalar giving the requested number of pools. This is
  forwarded only to families where the native constructor accepts a free
  row-count argument. For Polynomial Pools, `J` may be used only to
  infer \\n_l = J/q\\ when that ratio is an integer.

- method:

  Optional character scalar giving a family-specific construction mode.
  Examples include `"pp"` or `"clinical"` for `family = "pbest"`,
  `"auto"`, `"random"`, or `"reed-solomon"` for `family = "separable"`
  and `family = "disjunct"`, and `"2d"` or `"3d"` for
  `family = "array"`.

- verify:

  Logical scalar. This is forwarded to families that expose an explicit
  verification option, namely `"separable"` and `"disjunct"`.

- seed:

  Optional integer scalar. This is forwarded only to families whose
  current constructor uses randomness, such as random separable/disjunct
  designs and the package-specific clinical P-BEST helper.

- ...:

  Additional family-specific arguments. Supported names are:

  `nl`

  : Number of PP layers for `family = "pp"` or the PP-based `"pbest"`
    path.

  `reorder`

  : Logical reorder flag for `family = "hyper"`.

  `g`

  : Pool size for `family = "dorfman"`.

  `r`, `c`

  : Grid dimensions for the two-dimensional array path.

  `d1`, `d2`, `d3`

  : Grid dimensions for the three-dimensional array path.

  `v`, `k`, `lambda`

  : BIBD or Kirkman parameters.

- verbose:

  Logical scalar; if `TRUE`, emit a short message describing the chosen
  dispatch path.

## Value

A binary pooling matrix returned by the selected constructor, usually of
class `dgCMatrix`. The matrix is returned directly, and carries an
additional `"poolmatrix"` attribute containing the selected family,
dispatch method, and the key arguments used by the wrapper. The return
value is the stage-1 design matrix \\\mathbf{M}\\ only.

## Details

Let \\\mathbf{M} \in \\0,1\\^{J \times N}\\ denote a pooling design
matrix, where \\J\\ is the number of pools and \\N\\ is the number of
individuals. The wrapper `PoolMatrix()` is a constructor-only dispatcher
over existing matrix constructors. It returns \\\mathbf{M}\\ and stops
there. In particular, it does not handle adaptive versus non-adaptive
workflow selection, retesting scenarios, stage-2 protocol logic, or
decoder behavior. Those concerns belong in separate functions or in
package documentation, not in this wrapper.

The function also does not solve a universal inverse problem of the form
"given \\d\\, construct the unique matrix." The symbol \\d\\ has
different meanings across the supported families, and some families do
not use \\d\\ at all.

The dispatch rules are:

- `family = "pp"`:

  Dispatch to
  [`pp_matrix`](https://myaseen208.github.io/ppgt/reference/pp_matrix.md)
  using \\q\\, \\d\\, \\n_l\\, and optional \\N\\.

- `family = "pbest"`:

  Dispatch either to the standard PP-based 48-pool family through
  [`pp_matrix`](https://myaseen208.github.io/ppgt/reference/pp_matrix.md)
  with \\(q,d,n_l,N) = (8,3,6,384)\\, or to the package-specific
  clinical helper
  [`pbest_clinical_matrix`](https://myaseen208.github.io/ppgt/reference/pbest_clinical_matrix.md)
  when `method = "clinical"`.

- `family = "hyper"`:

  Dispatch to
  [`hyper_matrix`](https://myaseen208.github.io/ppgt/reference/hyper_matrix.md)
  using \\N\\, \\J\\, and \\q\\.

- `family = "separable"`:

  Dispatch to
  [`SeparableMatrix`](https://myaseen208.github.io/ppgt/reference/SeparableMatrix.md)
  using \\N\\, \\d\\, optional \\J\\, and the selected method.

- `family = "disjunct"`:

  Dispatch to
  [`DisjunctMatrix`](https://myaseen208.github.io/ppgt/reference/DisjunctMatrix.md)
  using \\N\\, \\d\\, optional \\J\\, and the selected method.

- `family = "dorfman"`:

  Dispatch to
  [`dorfman_matrix`](https://myaseen208.github.io/ppgt/reference/dorfman_matrix.md)
  using \\N\\ and the explicit pool-size argument `g`.

- `family = "array"`:

  Dispatch to
  [`array_matrix`](https://myaseen208.github.io/ppgt/reference/array_matrix.md)
  or
  [`array_matrix_3d`](https://myaseen208.github.io/ppgt/reference/array_matrix_3d.md)
  according to `method`.

- `family = "bibd"`:

  Dispatch to
  [`bibd_matrix`](https://myaseen208.github.io/ppgt/reference/bibd_matrix.md)
  using \\v\\, \\k\\, and \\\lambda\\.

- `family = "hypercube"`:

  Dispatch to
  [`hypercube_matrix`](https://myaseen208.github.io/ppgt/reference/hypercube_matrix.md)
  using \\q\\ and \\d\\.

- `family = "kirkman"`:

  Dispatch to
  [`kirkman_matrix`](https://myaseen208.github.io/ppgt/reference/kirkman_matrix.md)
  using \\v\\.

- `family = "pg"`:

  Dispatch to
  [`pg_matrix`](https://myaseen208.github.io/ppgt/reference/pg_matrix.md)
  using \\q\\.

Family-specific parameters remain explicit. In particular, the wrapper
does not impose \\d\\-only semantics on families such as HYPER, Dorfman,
array, BIBD, Kirkman, or projective-plane designs, where \\d\\ is not
the native defining parameter. Likewise, calling `PoolMatrix()` should
be read only as "construct \\\mathbf{M}\\ for the chosen family" and not
as "run the complete testing workflow" for that family.
