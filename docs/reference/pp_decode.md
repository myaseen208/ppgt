# Complete PP Decoding Pipeline

Full detection pipeline combining COMP filtering, GPSR scoring,
exhaustive verification, and an optional three-way probabilistic
classification (positive / suspected / negative) following Zismanov et
al. (2024).

## Usage

``` r
pp_decode(M, y, k_max = NULL, ct_threshold = 40, verbose = TRUE, ct = NULL)
```

## Arguments

- M:

  Binary pooling matrix \\\mathbf{M} \in \\0,1\\^{J \times N}\\,
  typically created by
  [`pp_matrix`](https://myaseen208.github.io/ppgt/reference/pp_matrix.md).
  Its rows index pools \\j \in \\1,\ldots,J\\\\ and its columns index
  individuals \\i \in \\1,\ldots,N\\\\.

- y:

  Numeric vector of length \\J\\ containing observed pool outcomes.
  Allowed inputs are either binary observations \\Z_j \in \\0,1\\\\ or
  Ct-like values interpreted using `ct_threshold`.

- k_max:

  Integer scalar or `NULL` giving the maximum number of positives to
  consider during exact verification. When `NULL` (default), the value
  is read from `attr(M, "pp")$k_max` if present. A hard numeric value
  supplied by the caller always takes precedence. If neither source
  provides a value, a fallback of 5 is used with a warning.

- ct_threshold:

  Numeric scalar giving the positivity threshold used when `y` contains
  Ct-like values. The default is `40`.

- verbose:

  Logical scalar; if `TRUE` (default), print progress messages
  describing the decoding path taken.

- ct:

  Numeric vector of length \\N\\ containing per-individual Ct values, or
  `NULL`. Named or unnamed; NAs are treated as unknown (Ct criterion
  skipped for that sample). When non-`NULL`, enables the noise model and
  three-way classification. When `NULL` (default), the function behaves
  identically to previous versions except that the uniqueness check
  still populates `$suspected`.

## Value

A list with components:

- positives:

  Integer vector of confirmed positive sample indices (1-indexed). These
  meet all three-way classification criteria.

- n_positives:

  Integer; number of confirmed positives.

- suspected:

  Integer vector of suspected sample indices (require retesting). Empty
  when all decoded positives pass classification.

- n_suspected:

  Integer; number of suspected samples.

- candidates:

  Integer vector of all COMP candidates.

- n_candidates:

  Integer; number of COMP candidates.

- error:

  Integer; number of pool mismatches (0 = perfect match).

- method:

  Character; description of method used.

## Details

The current package workflow applies COMP filtering, optional GPSR
scoring, exact subset verification, and an optional three-way
classification layer.

## Algorithm Steps

1.  **COMP filtering**: identify sure negatives and candidates.

2.  **Early exit**: if the candidate count is \\\leq k\_{max}\\, accept
    all candidates as decoded positives.

3.  **GPSR scoring**: if there are too many candidates, rank them by
    GPSR scores.

4.  **Exhaustive verification**: search the top candidate sets for the
    best subset under \\\\\psi(\mathbf{M}\hat{\mathbf{x}}) -
    \mathbf{y}\\\_1\\.

5.  **Three-way classification**: optionally split decoded candidates
    into confirmed positives and suspected samples that require
    retesting.

## Handling Ct Values

Pool results in `y` can be supplied either as binary outcomes or as
Ct-like values interpreted with `ct_threshold`.

- **Binary**: \\Z_j \in \\0,1\\\\.

- **Ct values**: 0 indicates an undetected pool, and \\0 \< \mathrm{Ct}
  \< 40\\ indicates a detected pool.

When quantitative Ct-like values are available, the package GPSR scoring
layer uses them as a proxy for signal strength.

## Noise Model

When per-sample Ct values are supplied through `ct`, the current package
implementation models the false-negative probability as \$\$P(\text{FN}
\mid \text{Ct}) = \frac{1}{1 + \exp\bigl(-(\text{Ct} - 29) \times
0.5\bigr)}.\$\$ This places \\P(\text{FN}) = 0.5\\ at \\\text{Ct} = 29\\
and \\P(\text{FN}) \approx 0.95\\ near \\\text{Ct} \approx 35\\, which
is consistent with the paper's strong-positive threshold \\\text{Ct}
\leq 36\\.

## Three-Way Classification

Each decoded candidate is assigned to one of three categories:

- **Positive**:

  All identifying pools are positive; Ct is \\\leq 36\\ when available;
  \\P(\text{FN} \mid \text{Ct}) \leq 0.95\\; and the sample has at least
  one unique identifying pool.

- **Suspected**:

  Pool results are compatible with positivity, but Ct is above 36, no
  unique identifying pool is present, or \\P(\text{FN}) \> 0.95\\.

- **Negative**:

  The sample is eliminated by COMP because at least one identifying pool
  is negative.

A unique identifying pool is a positive pool that contains the sample
but no other decoded positive, matching criterion (b) in the paper. When
`ct = NULL`, the Ct and false-negative criteria are skipped and the
uniqueness rule still applies.
